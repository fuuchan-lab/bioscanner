# 生体スキャナー BioScanner

スマートフォンのカメラをかざした範囲に生き物がいそうかを探す、インストール不要のウェブアプリです。映像の**動き**、その動きの**律動性**、そして**色調**の3つを合成して判定します。

端末内だけで処理し、映像を外部へ送信することはありません。検出時の静止画を記録する機能がありますが、保存先はその端末のブラウザ内だけです。

---

## はじめに — できないこと

**ブラウザから温度センサー(サーモグラフィ)は使えません。** スマートフォンのカメラは可視光を捉えるもので熱を見ていないため、本当の体温測定は原理的に不可能です。「赤外線で体温を検知する」と称するスマホアプリは、実際には別の情報か演出に基づいています。

このアプリはその点をごまかさず、温度の代わりに**色調からの推定**を「温感」として示し、UI上でも推定であることを明示しています。

そして最も重要な点として、**結果は生き物の存在を確証するものではありません。** 風に揺れる葉、点滅する光、はためく布などを生体と誤判定します。人命・安全・医療に関わる判断には絶対に使用しないでください。

---

## 仕組み

映像を 48 × 36 の格子に縮小し、各セルの輝度を 15 Hz で約 8.5 秒ぶん(128フレーム)保持します。そこから3つの指標を取り出します。

### 1. 動き(MOTION) — 実測

フレーム間の輝度差の指数移動平均。セル単位で持つため、画面のどこが動いているかが分かります。

### 2. 律動(RHYTHM) — 実測

**このアプリの核になる部分です。** 動いているだけでは生き物とは限りません。そこで各セルの輝度の時系列を Goertzel 法で周波数解析し、次の帯域にピークが際立つかを調べます。

| 帯域 | 周波数 | 相当するもの |
|---|---|---|
| 呼吸帯 | 0.23 – 0.59 Hz | 約 14 – 35 回/分 |
| 脈拍帯 | 0.82 – 3.05 Hz | 約 49 – 183 回/分 |

#### 際立ちの測り方が要点

ピークの大きさを**全帯域の平均**と比べるのは誤りです。風に揺れる草木のような 1/f 的な信号は周波数が低いほど強いため、高周波まで含めた平均と比べれば、周期性がまったくなくても必ずピークが際立って見えてしまいます。

そこで**ピーク周辺の背景**と比べます。ピークから ±6 ビンの窓を取り、そこから Hann 窓の主ローブが広がる ±2 ビンを除いた残りの**中央値**を背景とし、山が地の高さからどれだけ抜きん出ているかを測ります。1/f 信号ではピークが背景の傾きの上に乗っているだけなので比は小さくなり、真の正弦的な信号では山だけが突出するので比が大きくなります。

合成信号で検証した際立ちの分布は次の通りです。

| 区分 | 中央値 |
|---|---|
| 呼吸・脈拍(正弦的) | 11 – 26 |
| 風・水面・センサーノイズ(広帯域) | 2 – 5 |

この分布から 7 を下限、18 を上限として 0〜1 に写しています。あわせて、センサーノイズだけで偶然ピークが立つのを防ぐため信号の標準偏差による振幅ゲートを掛けています。

#### 倍音を背景から除く

呼吸は正弦波ではないので必ず倍音(2f)を持ちます。呼吸帯の上半分(約 0.4 Hz 〜、24回/分〜)では、この倍音がちょうど背景の窓に入り、背景を底上げして本物の呼吸の際立ちを 5 前後まで潰していました。小動物の呼吸数はこの帯域に入ります。

そこで倍音の位置(補間したピーク位置の2倍)の ±1.5 ビンも背景から除き、背景が4ビンに満たなくなったら窓を ±10 ビンまで広げます。合成信号の検証で、呼吸の検出率は **18% → 82%** に上がりました(広帯域の誤検出率は 1% 未満のまま)。

検出された周期は「呼吸帯 18/分」のように画面に表示されます。

#### 一定周期の除外 — 周期の「揺らぎ」を見る

ある瞬間の周波数解析だけでは、周期的に動く非生物(扇風機・振り子・明滅する光)と呼吸・脈拍は区別できません。どちらも同じように鋭いピークを持つからです。

違いが出るのは**時間をかけたときの周期の揺らぎ**です。機械の周期はほとんど変わらないのに対し、生き物の呼吸数や心拍数は数秒単位で揺らぎます。そこでセルごとにピーク周波数を追跡し、揺らぎが小さすぎるものを機械的な周期として律動を最大 85% 弱めます。

- ピーク位置は Hann 窓の主ローブ3点からガウス補間して小数ビンで求めます(機械の周期でも推定誤差は約 0.02 ビン)。
- 揺らぎは指数移動の分散(時定数 約21秒)で測ります。8.5秒の窓は大きく重なるため、揺らぎを見るには窓を何本も跨ぐ必要があり、**判定が効き始めるのは全帯域の解析が始まってから約 8〜15 秒後**です。それまでは従来どおり検出されます。
- 揺らぎは周波数に対する比ではなく**ビン単位の絶対量**で判定します(0.035 ビン以下を機械とみなし、0.06 ビンまでで段階的に戻す)。推定誤差はビン単位でほぼ一定なので、比で見ると低い周波数ほど機械の周期が揺らいで見え、ゆっくりした振り子を取り逃がしたためです。
- 弱めたときは判定の下に「一定周期を除外」と表示します。

| 合成信号の誤検出率 | 12秒(判定が効く前) | 30秒(判定が効いた後) |
|---|---|---|
| 扇風機 | 89% | 6% |
| 振り子 | 81% | 7% |
| 明滅する光 | 87% | 4% |

#### この方法でも区別できないもの

- **風に揺れる枝(共振)は区別できません。** 固有振動数を持つ枝を風が不規則に叩くと、周期が生き物と同じ程度に揺らぎます(合成信号で 39% を誤検出)。
- **非常に規則正しい脈拍・呼吸は弱められることがあります。** 心拍の揺らぎがごく小さい個体では、機械と同じ程度の揺らぎしか見えないことがあります。合成信号では、脈拍の検出率は判定が効く前の 54%(12秒)から 51%(30秒)に下がりました。

### 3. 温感(WARMTH) — **推定**

色相と彩度から肌・毛色らしさを推定したものです。**温度ではありません。** 橙〜肌色の色相帯にあり、彩度があり、白飛び・黒潰れしていないセルを暖色として評価します。

### 4. 個体の大きさ — 角寸法は実測、物理サイズは距離次第

**カメラ1台では距離が分からないため、物理的な大きさは原理的に出せません。** 測れるのは角寸法(視野に占める角度)までで、`物理サイズ = 角寸法 × 距離` だからです。

そこでアプリは次を分けて表示します。

- **角寸法** — 仮定ゼロの実測値。常に表示されます。
- **物理サイズ** — 距離を与えて初めて算出。距離の求め方は2通りあります。

| 距離の求め方 | 内容 |
|---|---|
| 手動で入力 | 対象までの距離を指定する。確実だが目測精度に依存する |
| 傾きから | 端末の傾きとカメラの高さから、平らな地面に立つ対象までの距離を幾何で求める |

傾きから求める方式は、光軸の伏角を端末座標の -z 軸の鉛直成分から出しています(`asin(cos β · cos γ)`)。この式は縦持ち・横持ちに依らず成立します。対象の足元の角度を足した伏角 δ に対し、距離は `カメラ高さ / tan δ` です。**地面が平らで、対象が地面に接していることが前提**で、水平より上を向いている場合は距離が決まらないため表示しません。

サイズは**範囲**で表示します。外接矩形が 48×36 の解析格子の刻みしか持たないため、幅1セル分を誤差として振っています。距離5mでは1セル ≈ 14cm、距離0.5mでは ≈ 1.4cm です。

画角は既定で水平68°(一般的なスマートフォンの主カメラ相当)としていますが、ブラウザから実際の画角を取得する方法はないため、**設定で調整できます**。画角の誤差はそのまま大きさの誤差になります。

### 合成と検出

`スコア = 0.40 × 動き + 0.40 × 律動 + 0.20 × 温感`

3×3 平均で空間平滑化したのち、しきい値を超えるセルを連結成分としてまとめ、上位3件を枠で表示します。最有力の領域の強さが画面左下の判定値になります。

### 暗所 — ノイズに合わせたしきい値

暗い場所ではセンサーの増幅が上がり、静止した場面でもフレームごとに輝度がばらつきます。以前は「動いた」とみなす残差が固定値(2.5)だったため、ノイズが大きいと

- 画面全体の動きのスコアが底上げされ、何もない場所まで反応する
- ほぼ全セルが「動いた」ことになってカメラの移動と誤判定し、バッファを捨て続けて**判定がまったく出なくなる**

という問題がありました。

そこで毎フレーム、フレーム間の残差の分布からノイズの大きさ σ を推定します。静止した場面の残差は |N(0, 2σ²)| に従うので、その下位30%点 = 0.545σ から σ が求まります。下位で見るのは、被写体が画面の大半を占めても動いていない部分だけで測るためです。これに合わせて

- 「動いた」とみなす残差を `max(2.5, 3.5σ)` に
- 動きのスコアの床を `max(0.4, 1.3σ)` に

引き上げます。明るい場面では従来と同じ値のままです。

| ノイズ σ | カメラ移動と誤判定した時間 | 静止したセルの動きのスコア |
|---|---|---|
| 2 | 0% → 0% | 37% → 3% |
| 4 | **100% → 0%** | 66% → 4% |
| 8 | **100% → 0%** | 97% → 7% |

律動の解析は、もともとノイズに強いため変えていません。際立ちは山と背景の比なので、ノイズが増えれば背景も同じだけ上がり、ノイズだけで際立ちが出ることはありません(σ=8 でも誤検出 0%)。ただし被写体の動きがノイズに埋もれれば検出率は当然下がります。暗所では状態表示に「暗所 — 感度低下」(ライトがあれば「暗所 — ☀ を推奨」)と出ます。

### カメラの移動検出

カメラ自体が動くと時系列バッファが無意味になるため、移動を検出したらバッファを破棄して取得をやり直します。

このとき、画面全体の動き量の**合計**ではなく、**動いているセルの割合**で判定しているのが要点です。合計で見ると、大きな動物が横切っただけで「移動中」と誤判定して、せっかく貯めたバッファを捨ててしまいます。カメラのパンならほぼ全セルが動き、被写体の移動なら一部しか動きません。

### 段階的な判定

| 経過 | 状態 | 内容 |
|---|---|---|
| 〜 3.2 秒 | 基準取得 | 判定なし |
| 3.2 秒 〜 | 走査中(暫定) | 動きと温感のみ。合成値は構造的に 60% 止まりになります |
| 9 秒 〜 | 走査中(全帯域) | 律動解析が有効。ここからが本来の精度です |

## 使い方

1. スマートフォンのブラウザで公開 URL を開きます(カメラは HTTPS でのみ使用できます)。
2. 「カメラを起動」を押し、カメラの使用を許可します。
3. 調べたい方向にかざし、**できるだけ静止させます**。
4. 画面上部の状態表示が「走査中 — 全帯域」になれば、律動解析まで有効です。

### 操作

| 操作 | 内容 |
|---|---|
| 感度 低 / 中 / 高 | 検出のしきい値。誤検出が多ければ「低」、見逃しが多ければ「高」 |
| 記録 | いまの画面を静止画として記録 |
| 一覧 | 記録の一覧。拡大表示・保存/共有・削除、自動記録の入/切 |
| ▚ | ヒートマップの表示切替 |
| ☀ | ライト(対応端末のみ表示) |
| ⇄ | 前面 / 背面カメラの切替(起動前は覆いの「背面カメラ / 前面カメラ」でも選べ、選択は次回も保たれる) |

### 記録

反応が「生体の可能性」(46%)を超えると、**自動で静止画を記録**します。反応が続いている間(最長8秒)で最も強かった瞬間を1枚だけ残し、反応が 30% 未満に下がるか 60 秒経つまでは次を記録しません。同じ対象を写し続けても記録が溢れないようにするためです。

静止画には熱マップと検出枠が重なり、下の帯に日時・反応・周期・内訳・大きさが焼き込まれるので、画像だけで後から状況が分かります。

記録は**その端末のブラウザ内(IndexedDB)にだけ**保存され、外部には送信されません。最大 200 件で、古いものから消えます。一覧の「保存・共有」で写真アプリへの共有やファイル保存ができます。自動記録は一覧の画面で切れます。プライベートモードなど保存領域が使えないブラウザでは記録できません。

### 前面カメラ

前面カメラ(自撮り側)でも同じ解析が使えます。画面は鏡のように左右反転して表示し、手の動きと映像の向きが一致するようにしています。反転は解析の格子の段階で行うので、検出枠や数値の文字は裏返りません。記録の静止画も画面と同じ向きで保存されます。

- 起動前に覆いの「背面カメラ / 前面カメラ」で選ぶか、動作中に ⇄ で切り替えます。選択は次回も保たれます。
- 切り替えるときは今のカメラを閉じてから次を開きます(多くの Android 端末は2台のカメラを同時に開けないため)。
- 指定した向きのカメラが無い端末(パソコンなど)では、使えるカメラで起動します。
- 「傾きから」距離を求める方式も前面カメラに対応しています(光軸の向きが逆なので伏角の符号を反転)。
- 前面カメラは背面より画角が狭い機種もあります。大きさを出すときは設定の画角を合わせてください。ライトは前面カメラでは使えません。

ホーム画面に追加するとスタンドアロンで起動し、Service Worker により**電波のない場所でもオフラインで動作**します。

## 技術的な制約と注意

- **HTTPS 必須。** `getUserMedia` は安全なコンテキストでしか動きません。`file://` で直接開いても動作しません。
- **iOS Safari** では `playsinline` 属性が必須です(指定済み)。
- 暗所では映像ノイズが増え、律動の誤検出が起こりやすくなります。
- **周期的に揺れるものは、はじめの十数秒は生体として検出されます。** 周期が一定なもの(扇風機・振り子・明滅する光)はその後弱められますが、風に揺れる枝のように不規則に揺れるものは区別できません。上記「一定周期の除外」を参照してください。
- 風に揺れる草木や水面のゆらぎは、際立ちの測り方を背景比に変えたことで大きく抑制されていますが、ゼロにはなりません。
- カメラの移動判定のしきい値は実地で調整が必要な場合があります。`index.html` 内の `MOVE_ON` / `MOVE_OFF`(0.55 / 0.32)を変更してください。

## ローカルで動かす

HTTPS が必要なため、ただファイルを開くだけでは動きません。`localhost` は例外的に安全なコンテキストとして扱われるので、ローカルサーバーを立てれば検証できます。

```bash
# Python がある場合
python -m http.server 8000
# → http://localhost:8000 を開く
```

同じ Wi-Fi 上の実機で試す場合は、`localhost` ではないため HTTPS が必要です。公開 URL(GitHub Pages)を使うのが簡単です。

## 検証スクリプト

解析の数値は、合成信号に通して確かめられます。`index.html` の「解析の核」(`==CORE:BEGIN==` 〜 `==CORE:END==` の区間)を**そのまま取り出して**動かすので、アプリと検証で別々のコードがずれる心配がありません。

```bash
node tools/verify.mjs              # 各条件 300 試行
node tools/verify.mjs --n 1000     # 試行数を増やす
node tools/verify.mjs --diag       # 周期の揺らぎの分布も表示
node tools/verify.mjs --set STAB_LO=0.03,STAB_HI=0.05   # 定数を変えて試す(index.html は変えない)
```

Node.js 18 以上で動き、外部パッケージは要りません。乱数は種付きなので、同じ引数なら毎回同じ数字が出ます。

合成する信号は次の通りです(どれも1セルの輝度の時系列、40秒)。

| 区分 | 信号 |
|---|---|
| 生体 | 呼吸(15–33回/分、呼吸数が 4–12% 揺らぐ非対称波形)、脈拍(55–165回/分、呼吸性の揺らぎ 1–6% とゆっくりした変動 1–4%) |
| 広帯域の非生体 | 風(1/f^α 雑音)、水面(0.5–3 Hz の帯域雑音)、センサーノイズのみ |
| 周期の一定した非生体 | 扇風機、振り子、明滅する光、風に揺れる枝(固有振動数を持つ減衰振動子を雑音で駆動) |

律動スコア 0.5 以上を「検出」とし、全帯域の解析直後(12秒)と、じっくり見た後(30秒)で数えます。センサーノイズ σ=0.7、各 500 試行での結果は次の通りです。

| | 12秒 | 30秒 |
|---|---|---|
| 生体の検出率 | 68% | 66% |
| 広帯域の非生体の誤検出率 | 0.9% | 0.7% |
| 周期の一定した非生体の誤検出率 | 74% | 14% |

脈拍の検出率(約 50%)が低めなのは、振幅をノイズと同程度まで小さくした個体を含めているためです(振幅がノイズの2倍以上ならほぼ 100% 検出します)。周期の一定した非生体の 14% は、ほとんどが区別できない「風に揺れる枝」です。

合成信号での数字であり、実際の映像での精度を保証するものではありません。しきい値を変えるときの比較用の物差しとして使ってください。

## 構成

```
index.html              アプリ本体(CSS・JS を含む単一ファイル)
tools/verify.mjs        合成信号による検証(index.html の解析の核を取り出して動かす)
sw.js                   Service Worker(オフライン対応)
manifest.webmanifest    PWA マニフェスト
icons/                  アイコン一式(icon-source.png から生成)
icon-source.png         アイコンの元画像(白地に黒のシルエット)
```

アイコンは元画像の余白を自動で切り詰め、黒を琥珀色・白を地色に転換して生成しています。輝度をそのまま不透明度に使うため線の縁が保たれます。`icon-maskable-512.png` は外周が切り落とされても図像が残るよう内側に寄せてあります。

**アプリやアイコンを更新したら `sw.js` の `CACHE` の版を上げてください。** 上げないと、ホーム画面に追加済みの端末が古い内容を持ち続けます。

外部依存は Google Fonts のみで、読み込めない場合もシステムフォントにフォールバックします。
